# 보비 재무상담 (consult)

보비 콘텐츠 화면으로 편입된 재무상담 서비스입니다. 좌측 GNB `재무상담` 메뉴로 들어옵니다.
빌드 도구 없이 브라우저로 바로 열립니다.

- 기획 원본: `디자인팀_인수인계_v1_20260927.md` (구조·순서·문구·계산은 이 문서가 기준)
- 숫자·구조는 기획 문서 기준을 따릅니다. **문구는 2026-09-30 자로 비즈니스 문어체로 전면 교체**했습니다(아래 문체 규칙).

## 사이트맵 (2026-09-29 확정)

```
재무상담서비스 = 상담
├─ 리스트                        index.html
└─ 새로운 상담하기
     ├─ 상담
     │   기본정보  ›  수입지출(현금흐름표)  ›  자산·부채  ›  재무재표
     │   basic.html  cashflow.html         assets.html  statement.html
     │   └ 기본정보 하위: 인적정보 · 상담목표 · 특이사항 · 이전 상담(있을시)
     └─ 상담결과                 result.html
          요약(솔루션·서머리) · 지출에 대한 결과 · 저축에 대한 결과
          · 목표별(비상금·주택구매·결혼자금·자녀학비·노후·기타)
     └─ 혜택·보조금 (별도 화면)   benefits.html
```

- **혜택·보조금은 상담 안에 있지만 별도 화면**(`benefits.html`)입니다. 상담결과 안의 블록이나 탭으로 넣지 않습니다.
- 진입은 **탐색 줄 오른쪽 끝의 `공공 혜택` 링크** 하나뿐입니다(`.ct-keylink` — 방패 아이콘 + 건수 + 화살표).
  같은 줄에 탭·단계가 있어 알약 버튼은 쓰지 않고, 배경 없는 액션 링크로 둡니다(hover 때만 `--brand-pale`).
  상담결과는 `.ct-subtabs`(요약…다음 상담) 줄에, 01–04는 그 자리에 해당하는 `.ct-steps`(단계) 줄에 둡니다.
  둘 다 `margin-left: auto`로 우측정렬이고, 헤더에는 두지 않습니다.
- `?from=<화면>`을 물고 가서 열었던 화면으로 돌아갑니다.
- **신규 작성 중에는 이 버튼이 안 나옵니다.** 조회에 필요한 가구 조건이 아직 없기 때문입니다.
  `data-only="demo"`가 붙어 있어 빈 상태에서 숨겨집니다.
- 비상금·작년 기록은 화면이 없어서, 나가기는 위 `재무상담 목록` 링크와 겹쳐서 헤더에서 뺐습니다.
- 4단계는 `.ct-steps`로 서로 링크돼 있어 실제로 이동합니다. 상담결과는 구분선 뒤에 따로 둡니다.

## 화면 안 동작 (`_actions.js`)

저장·계산은 없지만 **눌러 보는 것은 전부 반응합니다.** 마크업에 아래 속성만 달면 동작이 붙습니다.

| 속성 | 동작 |
|---|---|
| `.ct-seg > div` | 한 칸 선택 (주거 형태 · 수입 형태 · 목표 기간) |
| `.ct-sw[data-toggle="키"]` | 토글. 같은 `data-toggle-target="키"` 요소를 접고 폅니다 |
| `.ct-chip[data-chip]` | 여러 개 선택 (추가 조건) |
| `.ct-subtabs > div[data-tab="키"]` | 탭 전환. `data-tab-panel="키"` 패널을 보입니다 |
| `tr[data-exp]` | 다음 `tr.exp` 를 접고 폅니다 (부채 상세) |
| `td[data-act="del"]` | 그 줄 삭제 (딸린 `tr.exp` 도 함께) + 토스트 |
| `.ct-add[data-add="tplId"]` | `<template>` 의 줄을 표 끝에 추가하고 첫 칸에 커서 |
| `.ct-more[data-more="키"]` | `data-more-item="키"` 를 모두 펴고 자신은 사라짐 |
| `.ct-tot .li[data-cat="이름"]` | 수입지출 좌측 선택 → 우측 상세 표 교체 |
| `.ct-pill[data-weeks="N"]` | 다음 상담일을 상담일 + N주로. 달력·문장까지 갱신 |
| `.ct-cal .days div[data-d="N"]` | 다음 상담일을 그 날짜로 |
| `[data-print]` | `window.print()` |
| `[data-todo="문구"]` | 아직 없는 기능 — 토스트로 알림 |
| `.ct-in` | 직접 고쳐 쓰기(`contenteditable`). 힌트는 첫 입력에 지워지고, 비우면 되돌아옵니다 |

- **줄 추가는 `<template id="tpl-*" data-row-for="<tbody id>">`** 한 벌로 관리합니다. 빈 상태 안내 줄(`tr[data-blank]`)은 첫 추가 때 사라집니다.
- **수입지출 소분류**(`_actions.js` 의 `DETAIL`)는 좌측 합계에 맞춰 나눈 **예시값**입니다. 실제 항목 체계가 정해지면 교체해야 합니다.
- 신규 작성(`?demo=1` 없음)에서는 소분류 이름만 두고 금액은 비워 두며, `4주 후` 같은 선택도 풀려 있습니다.

## 화면 상태 — 빈 값이 기본

**새로운 상담하기로 들어오면 모든 칸이 비어 있고 힌트만 보입니다.** 예시 값을 보려면 주소 뒤에 `?demo=1`을 붙입니다.
상담 리스트에서 기존 회차의 `결과 보기`를 누르면 `result.html?demo=1`로 열립니다.

마크업은 한 벌만 두고 `_state.js`가 `data-*` 속성으로 두 상태를 만듭니다.

| 속성 | 뜻 |
|---|---|
| `data-hint="예) 김민준"` | 빈 상태에서 보여 줄 힌트 (회색 `--ink-4`) |
| `data-demo="김민준"` | `?demo=1`일 때 채울 값 |
| `data-empty="—"` | 힌트 없는 칸의 빈 상태 표시 (기본 `—`) |
| `data-only="demo"` | 예시에서만 보이는 블록 |
| `data-only="empty"` | 빈 상태에서만 보이는 블록 |

- 빈 상태에서는 세그먼트 선택·포커스 테두리·진행 막대·강조 색이 모두 풀립니다.
- 계산 화면(재무재표·상담결과)은 빈 상태에서 `.ct-blank` 안내 카드와 '적으러 가기' 버튼을 보여 줍니다.
- 상담결과의 **솔루션(설계사가 적는 칸)과 다음 상담**은 빈 상태에서도 적을 수 있게 힌트만 넣어 두었습니다.
- `?demo=1`로 열면 단계 이동 링크에 자동으로 `demo=1`이 붙어 예시 상태가 유지됩니다.

공용 자산은 repo 것을 그대로 씁니다. 이 폴더에 사본을 두지 않습니다.

```
../../styles/tokens.css      디자인 토큰 + Pretendard Variable
../../styles/concept-a.css   .cA 테이블 기본 · .bobi td.amt (금액 우측정렬)
../../styles/concept-e.css   .layout / .cE / .emain / .back-btn / .ft 푸터
../../components/layout.js   injectShell('consult') — GNB·아이콘·푸터 주입
```

## 화면별 메모

### 상담 리스트 (index.html)
- 내고객 목록(`customer/list.html`)과 같은 뼈대입니다: `.search-bar`(검색+정렬) → `.filter-bar`(필터) → `.list-panel`(`.table-head` + `.table-row`).
- 표 칸: 고객 · 회차 · 최초 상담 · 마지막 상담 · 다음 상담. **지역은 리스트에 넣지 않습니다**(고객 헤더에만 표시).
- **검색·정렬과 필터를 다른 줄로 나눴습니다.** 정렬은 검색바 오른쪽 `.sort-select`, 필터는 아래 `.filter-bar`의 라벨 붙은 pill 묶음입니다.
- 필터: 상태(전체 · 진행 중 · 다음 상담 있음 · 다음 상담 없음 · 상담일 지남) / 회차(전체 · 1 · 2–4 · 5 이상) / 최초 상담(전체 · 2026 · 2025).
  각 pill에 건수를 같이 보여 주고, 그 개수는 **'그 필터만 뺀' 나머지 조건 기준**으로 셉니다(누르면 0이 되는 칩이 안 생기게).
- 2회차 이상인 줄을 누르면 아래에 회차 목록(회차 · 날짜 · 결과 보기, 최근 순)이 펼쳐집니다. **회차별 결론 문구는 리스트에 넣지 않습니다.**
- 다음 상담 칸: 이어서 하기 / 일정 잡기(브랜드색), 상담일 지남(빨강).
- 데이터와 동작은 맨 아래 `<script>`의 `DATA`와 `render()`에 있습니다.

### 04 재무재표 (statement.html)
- 01–03에서 적은 내용을 **표로만** 모아 확인하는 화면입니다. 현금흐름표와 재무상태표(가진 것 / 갚을 것 / 순자산 + 막대).
- **원그래프는 여기 두지 않습니다.** 결과 맨 위에만 둡니다(기획 원칙).
- 각 표 오른쪽 위에 해당 단계로 돌아가 고치는 링크가 있습니다.

### 상담결과 (result.html)
- 상단 `.ct-subtabs`로 5개 블록을 오갑니다. 스크롤에 따라 현재 블록이 표시됩니다.
- ① 요약 — 흐름 문장 + **원그래프(5색 도넛 + 범례)**, 그 아래 정리: 왼쪽 고민·순자산 막대·목표 합계 / 오른쪽 솔루션(오늘의 결론 · 고민에 대한 오늘의 답 · AI 평가)
- ② 지출 — 시나리오별 월 잔액 막대(기준선 0)
- ③ 저축 — 순자산 비중 57%, 현재 월 저축 39.5 vs 필요 130.6
- ④ 목표별 — **목표마다 얼마나 모았나(목표 3개 진행 막대)** · 돈이 몰리는 때 · 목표 적기 표
  - 목표 종류 6종(비상금·주택구매·결혼자금·자녀학비·노후·기타)은 **카드의 분류 칩과 표의 `종류` 열**로 씁니다. 종류별 빈 카드를 늘어놓지 않습니다.
  - 예시 데이터: 가족 여행(기타) 100/400 · 차 바꾸기(기타) 200/1,500 · 첫째 대학 등록금(자녀학비) 300/2,400
- ⑤ 다음 상담 — 날짜 + 2·4·8주 후 + 달력. **혜택·보조금 블록은 없습니다**(탭 줄 우측 링크 → 별도 화면).

### 혜택·보조금 (benefits.html)
- 탐색 줄 우측의 `공공 혜택` 링크로만 들어가는 별도 화면입니다. `?from=<화면>`으로 돌아갈 곳이 정해집니다.
- 카드는 기관·종류 / 혜택명 / 지원 내용 / 조건 태그 + 우측에 신청 마감·정부24 링크. D-day·금액 강조·총액 요약은 두지 않습니다.

## 문체 규칙 (2026-09-30 변경)

기준은 **"문장이냐 아니냐"가 아니라 "내용이냐 군더더기냐"** 입니다.
문장이라서 지우는 게 아니라, 읽을 것을 가리는 보조 설명이라서 지웁니다.

### 남기는 것 — 결과를 말하는 문장

고객이 읽어야 할 결론·발견은 문장 그대로 둡니다. 이게 상담결과의 본문입니다.

- `520만 원이 들어와서 514만 원이 나가고, 6만 원이 남았어요.` · `들어온 돈 100원 중 1원이 남는 셈이에요.`
- `학원비가 늘면 한 달에 9만 원이 모자라요.`
- `자산 중 절반 조금 넘게가 온전히 우리 집 몫이에요.`
- `목표를 모두 지키려면 매달 130.6만 원이 필요해요.`
- 고객 발화 인용, 설계사가 적는 `상담 결론` · `요청 사항 답변`

### 지우는 것 — 보조 캡션

화면 보는 법·입력하는 법을 설명하는 군더더기는 삭제하거나 최소 표기로 줄입니다.

| 삭제·축약 | |
|---|---|
| 가운데 선이 0이에요. 02 수입지출에 적은 목표 금액으로 계산했어요. | → `단위 만원 · 기준선 0` |
| 막대 한 줄이 그 목표의 필요금액이에요 · 단위 만 원 | → `단위 만원` |
| 적은 그대로 고객에게 보여요 / 지난 한 달 카드·통장 내역을 보며 함께 적어요 | 삭제 |
| 내년 7월까지는 목표 3개가 겹쳐… (그래프가 이미 보여 줌) | 삭제 |

### 그 밖

- **UI 라벨·표 머리글은 명사구.** `지금 모으는 돈 39.5` → `현재 월 저축 39.5만원`
- **고지·안내는 비즈니스 문어체.** "받을 수 있다고 정해진 건 아니에요…" → "정확한 지원 조건 및 신청은
  정부24에서 확인하시기 바랍니다."
- **빈 상태는 상태 명사.** "아직 적은 빚이 없어요" → `등록된 부채 없음`

| 만 원 | 만원 |

## 표시 규칙
- 금액 단위는 만원. 빈칸 = 미입력, 0 = 없음. 미입력 항목은 합계에서 제외하고 `미입력 N건 제외`로 표기.
- '위험', '나쁨' 같은 판정 표현은 쓰지 않음.
- 화면 전체를 고객과 함께 봅니다. 고객에게 감출 칸을 만들지 않습니다.
- 긴 이름(혜택명 · 기관명 40자 이상)은 2줄에서 말줄임.
