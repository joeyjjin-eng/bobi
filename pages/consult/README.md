# 보비 재무상담 (consult)

보비 콘텐츠 화면으로 편입된 재무상담 서비스입니다. 좌측 GNB `재무상담` 메뉴로 들어옵니다.
빌드 도구 없이 브라우저로 바로 열립니다.

- 기획 원본: `디자인팀_인수인계_v1_20260927.md` (구조·순서·문구·계산은 이 문서가 기준)
- 숫자·구조는 기획 문서 기준을 따릅니다. **문구는 2026-09-30 자로 비즈니스 문어체로 전면 교체**했습니다(아래 문체 규칙).

## 사이트맵 (2026-09-29 확정)

```
재무상담서비스 = 상담
├─ 리스트                        index.html
└─ 새로운 상담하기
     ├─ 상담
     │   기본정보  ›  수입지출(현금흐름표)  ›  자산·부채  ›  재무재표
     │   basic.html  cashflow.html         assets.html  statement.html
     │   └ 기본정보 하위: 인적정보 · 상담목표 · 특이사항 · 이전 상담(있을시)
     └─ 상담결과                 result.html
          요약(솔루션·서머리) · 지출에 대한 결과 · 저축에 대한 결과
          · 목표별(비상금·주택구매·결혼자금·자녀학비·노후·기타)
     └─ 도구 (별도 화면 3개)
          혜택·보조금      benefits.html
          비상금           emergency.html
          작년 기록        lastyear.html
```

- **도구 3개는 상담 안에 있지만 별도 화면**입니다. 상담결과 안의 블록이나 탭으로 넣지 않습니다.
- 진입은 **탐색 줄 오른쪽 끝의 링크 묶음**뿐입니다(`.ct-toolset` 안에 `.ct-keylink` 3개 — 아이콘 + 이름 + 화살표).
  같은 줄에 탭·단계가 있어 알약 버튼은 쓰지 않고, 배경 없는 액션 링크로 둡니다(hover 때만 색만 바뀝니다).
  상담결과는 `.ct-subtabs`(요약…다음 상담) 줄에, 01–04는 그 자리에 해당하는 `.ct-steps`(단계) 줄에 둡니다.
  `.ct-keylink` 하나하나에 `margin-left: auto`가 걸려 있어 그냥 늘어놓으면 서로 밀어냅니다.
  그래서 `.ct-toolset`으로 한 번만 우측정렬하고 그 안에서 20px 간격으로 둡니다. 헤더에는 두지 않습니다.
- 건수 배지(`.n`)는 조회 결과 건수가 있는 `공공 혜택`에만 붙입니다. 비상금·작년 기록에는 두지 않습니다.
- `?from=<화면>`을 물고 가서 열었던 화면으로 돌아갑니다(`back-step` · `back-label`).
- 4단계는 `.ct-steps`로 서로 링크돼 있어 실제로 이동합니다. 상담결과는 구분선 뒤에 따로 둡니다.

## 화면 안 동작 (`_actions.js`)

저장·계산은 없지만 **눌러 보는 것은 전부 반응합니다.** 마크업에 아래 속성만 달면 동작이 붙습니다.

| 속성 | 동작 |
|---|---|
| `.ct-seg > div` | 한 칸 선택 (주거 형태 · 수입 형태 · 목표 기간) |
| `.ct-sw[data-toggle="키"]` | 토글. 같은 `data-toggle-target="키"` 요소를 접고 폅니다 |
| `.ct-chip[data-chip]` | 여러 개 선택 (추가 조건) |
| `.ct-subtabs > div[data-tab="키"]` | 탭 전환. `data-tab-panel="키"` 패널을 보입니다 |
| `tr[data-exp]` | 다음 `tr.exp` 를 접고 폅니다 (부채 상세) |
| `td[data-act="del"]` | 그 줄 삭제 (딸린 `tr.exp` 도 함께) + 토스트 |
| `.ct-add[data-add="tplId"]` | `<template>` 의 줄을 표 끝에 추가하고 첫 칸에 커서 |
| `.ct-more[data-more="키"]` | `data-more-item="키"` 를 모두 펴고 자신은 사라짐 |
| `.ct-tot .li[data-cat="이름"]` | 수입지출 좌측 선택 → 우측 상세 표 교체 |
| `.ct-pill[data-weeks="N"]` | 다음 상담일을 상담일 + N주로. 달력·문장까지 갱신 |
| `.ct-cal .days div[data-d="N"]` | 다음 상담일을 그 날짜로 |
| `[data-print]` | `window.print()` |
| `[data-todo="문구"]` | 아직 없는 기능 — 토스트로 알림 |
| `.ct-in` | 직접 고쳐 쓰기(`contenteditable`). 힌트는 첫 입력에 지워지고, 비우면 되돌아옵니다 |

- **줄 추가는 `<template id="tpl-*" data-row-for="<tbody id>">`** 한 벌로 관리합니다. 빈 상태 안내 줄(`tr[data-blank]`)은 첫 추가 때 사라집니다.
- **수입지출 소분류**(`_actions.js` 의 `DETAIL`)는 좌측 합계에 맞춰 나눈 **예시값**입니다. 실제 항목 체계가 정해지면 교체해야 합니다.
- 소분류 이름만 두고 금액은 비워 두며, `4주 후` 같은 선택도 풀려 있습니다.

## 화면 상태 — 빈 값이 기본

**모든 금액 칸은 비어 있는 채로 열립니다.** 미리 채워 두거나, 마우스를 올리면 값이 들어가는 동작은 두지 않습니다.
값은 상담사가 고객과 함께 직접 적습니다.

| 표시 | 뜻 |
|---|---|
| `data-hint="예) 김민준"` | 빈 칸에 보여 줄 안내 (회색 `--ink-4`). 글자 칸은 비어 있으면 CSS `::before` 로 뜹니다 |
| `.ct-in.hint` | 아직 안 적은 칸. 금액은 `미입력`, 만기는 `YYYY.MM` 으로 둡니다 |
| `.ct-in.num` | 금액 칸. 우측정렬 + `만원` 꼬리. `.pc` 는 `%`(금리), `.plain` 은 꼬리 없음(만기) |

- `_model.js` 의 `blank()` 이 모든 금액을 `null` 로 비웁니다. `SAMPLE` 은 항목 이름·묶음 구성을 담는 뼈대입니다.
- **목표는 금액만 비우는 게 아니라 줄째로 비웁니다**(`m.goals = []`). 아무것도 안 적었는데 `가족 여행·차량 교체·첫째 대학 등록금`이
  들어 있으면 고객이 적은 목표처럼 읽힙니다. 빈 상태에서는 `등록된 목표 없음` + `+ 목표 추가` 만 둡니다.
- **상담결과 ③ 지출은 02 를 안 적었으면 빈 상태(`.ct-blank`)로 둡니다.** 예전에는 숫자가 마크업에 박혀 있어
  아무것도 안 적어도 `학원비가 늘면 9만 원이 모자라요`가 떴습니다. 지금은 전부 모델에서 계산합니다.
- 적은 값은 `localStorage['bobi.consult']` 한 칸에 모여, 04 재무재표와 상담결과가 그대로 읽어 계산합니다.
- **저장 값에는 버전(`v`)이 찍힙니다**(`_model.js` 의 `VERSION`). 읽을 때 버전이 다르면 그 값을 버리고 빈 화면으로 시작합니다.
  뼈대(항목 구성·빈 값 규칙)를 바꿀 때는 `VERSION` 을 올려야 합니다. 안 올리면 화면 코드를 고쳐도
  브라우저에 남은 옛 값이 그대로 읽혀 바뀐 게 없어 보입니다(`blank()` 은 저장된 게 없을 때만 도는 함수라 손이 닿지 않습니다).
- `새로운 상담하기`(`basic.html?new=1`)는 `CT.reset()` 으로 저장 값을 지우고 주소에서 플래그를 뗍니다.
- 빈 상태에서는 세그먼트 선택·강조 색이 모두 풀려 있고, 합계는 0으로 나옵니다.
- 상담결과의 **솔루션(설계사가 적는 칸)과 다음 상담**도 빈 칸 + 안내만 둡니다.

공용 자산은 repo 것을 그대로 씁니다. 이 폴더에 사본을 두지 않습니다.

```
../../styles/tokens.css      디자인 토큰 + Pretendard Variable
../../styles/concept-a.css   .cA 테이블 기본 · .bobi td.amt (금액 우측정렬)
```

## 화면별 메모

### 상담 리스트 (index.html)
- 내고객 목록(`customer/list.html`)과 같은 뼈대입니다: `.search-bar`(검색+정렬) → `.filter-bar`(필터) → `.list-panel`(`.table-head` + `.table-row`).
- 표 칸: 고객 · 회차 · 최초 상담 · 마지막 상담 · 다음 상담. **지역은 리스트에 넣지 않습니다**(고객 헤더에만 표시).
- **검색·정렬과 필터를 다른 줄로 나눴습니다.** 정렬은 검색바 오른쪽 `.sort-select`, 필터는 아래 `.filter-bar`의 라벨 붙은 pill 묶음입니다.
- 필터: 상태(전체 · 진행 중 · 다음 상담 있음 · 다음 상담 없음 · 상담일 지남) / 회차(전체 · 1 · 2–4 · 5 이상) / 최초 상담(전체 · 2026 · 2025).
  각 pill에 건수를 같이 보여 주고, 그 개수는 **'그 필터만 뺀' 나머지 조건 기준**으로 셉니다(누르면 0이 되는 칩이 안 생기게).
- 2회차 이상인 줄을 누르면 아래에 회차 목록(회차 · 날짜 · 결과 보기, 최근 순)이 펼쳐집니다. **회차별 결론 문구는 리스트에 넣지 않습니다.**
- 다음 상담 칸: 이어서 하기 / 일정 잡기(브랜드색), 상담일 지남(빨강).
- 데이터와 동작은 맨 아래 `<script>`의 `DATA`와 `render()`에 있습니다.

### 04 재무재표 (statement.html)
- 01–03에서 적은 내용을 **표로만** 모아 확인하는 화면입니다. 현금흐름표와 재무상태표(가진 것 / 갚을 것 / 순자산 + 막대).
- **원그래프는 여기 두지 않습니다.** 결과 맨 위에만 둡니다(기획 원칙).
- 각 표 오른쪽 위에 해당 단계로 돌아가 고치는 링크가 있습니다.

### 상담결과 (result.html)
- 상단 `.ct-subtabs`는 **스크롤 이동이 아니라 패널 전환**입니다(`data-tab` ↔ `data-tab-panel`, 동작은 `_actions.js`).
- 탭은 4개, 순서 고정: **요약 · 현금흐름표 · 수입지출결산 · 재무상태표** (기획 문서 '상담 결과' 항 순서).

#### 요약 탭 — 상담에서 함께 보는 내용을 한 탭에 모읍니다
- ① 요약 — 흐름 문장 + **원그래프(5색 도넛 + 범례)**, 그 아래 왼쪽 솔루션(상담 결론 · 요청 사항 답변 · AI 평가) / 오른쪽 요청 인용 · 순자산 막대 · 목표 합계
- ② 지출 — 시나리오별 월 잔액 막대(기준선 0). 02를 안 적었으면 `.ct-blank`로 둡니다.
- ③ 저축 — 순자산 비중 · 현재 월 저축 vs 필요 월 저축
- ④ 목표별 — 목표 진행 막대 · 돈이 몰리는 때 · 목표 관리 표
  - 목표 종류 6종(비상금·주택구매·결혼자금·자녀학비·노후·기타)은 **표의 `종류` 열**로 씁니다. 종류별 빈 카드를 늘어놓지 않습니다.
  - 빈 상태면 카드·타임라인 모두 `등록된 목표 없음`.
- ⑤ 다음 상담 — 날짜 + 2·4·8주 후 + 달력. 맨 아래 `이전 / 상담 완료` 버튼도 이 탭에 있습니다.

#### 현금흐름표 탭
- 01–03에 적은 내용을 `구분(①②③) · 묶음 · 항목` 세 단계 표 한 장으로 모읍니다.
  `① 수입 − ② 생활비 − ③ 저축·부채상환 = 월 잔액`. **비중(%) 열은 두지 않습니다.**
- 금액이 0인 항목 줄은 숨기고, 아직 아무것도 안 적은 화면에서만 항목 이름을 모두 회색으로 보여 줍니다.

#### 수입지출결산 탭
- 기획 문서의 `수입 합계 − 비용 합계 = 손익`.
- **비용은 실제로 쓴 돈만 셉니다.** 저축과 부채 원금은 돈이 나가도 자산·부채가 움직이는 것이라 비용이 아닙니다.
  그래서 손익은 월 잔액과 다를 수 있고, 그 둘을 `비용에 넣지 않은 지출` 묶음으로 따로 보여 줍니다.

### 비상금 (emergency.html)
기획 문서 3장 '목표 · 작년 기록 · 비상금' 항의 비상금 묶음을 그대로 옮긴 화면입니다.

  - `준비할 개월` — `.ct-seg`(3·6·12) + 직접 적는 칸. **기준값은 직접 적는 칸**이고, 프리셋을 누르면 그 칸에 숫자를 써 넣습니다.
  - `부채 상환액 포함`(기본 켜짐) — 월 상환액을 생활비에 더합니다.
  - `생활비에서 뺄 묶음`(기본 꺼짐) — 켜면 묶음 칩이 펴지고, 고른 묶음을 생활비에서 뺍니다(표에 `제외` 표기 + 회색).
- 계산: `목표 비상금 = 월 기준 생활비 × 준비할 개월` · `버틸 수 있는 기간 = 현재 비상금 ÷ 월 기준 생활비`.
- **현재 비상금은 입력 칸이 아닙니다.** 03 자산·부채의 `유동자산` 합계를 그대로 읽습니다(기획 문서 기준).
- 3칸 요약은 `.ct-sum`(목표 − 현재 = 추가 적립 필요액)입니다. 빈 값이면 `—` + `.none`으로 회색 처리합니다.
- '적립 계획'은 02 저축 합계를 전부 비상금에 넣는다고 본 참고값입니다. 저축을 안 적었으면 `저축액 미입력`.
- 토글·칩·개월을 바꾸면 표·요약·막대가 전부 다시 계산됩니다(`_actions.js`가 먼저 클래스를 바꾸고, 그 뒤 이 화면의 `render()`가 돕니다).

  (`카드 사용액과 겹칠 수 있음` · `그해 넣은 돈 · 통장에 쌓인 총액은 아님`). 문체 규칙의 '남기는 것'에 해당합니다.

- '02 수입지출과 비교'는 **둘 다 연간으로 맞춥니다.** 작년 자료를 12로 나누면 어느 달에 썼는지 모르는 금액을

- **예시 금액은 자리 채우기입니다.** 항목 구성만 맞춰 둔 것이고, 숫자끼리는 맞아떨어지지 않습니다(자료 연동 시 교체).

고객이 읽어야 할 결론·발견은 문장 그대로 둡니다. 이게 상담결과의 본문입니다.

- `학원비가 늘면 한 달에 9만 원이 모자라요.`
- `자산 중 절반 조금 넘게가 온전히 우리 집 몫이에요.`
- `목표를 모두 지키려면 매달 130.6만 원이 필요해요.`
- 고객 발화 인용, 설계사가 적는 `상담 결론` · `요청 사항 답변`
